# SIH26102 — Data Pipeline Rules

## Pipeline

RAW SOURCES
→ PROFILING
→ CLEANING / NORMALIZATION
→ ENTITY MATCHING
→ MASTER DATASET
→ FEATURE ENGINEERING
→ ANOMALY DETECTION
→ DATABASE
→ FASTAPI
→ WEB FRONTEND

## Required ETL steps

### 1. Profile first
For every raw file report:
- row count
- columns
- data types
- null counts
- duplicate counts
- unique counts
- date formats
- amount formats
- candidate identifiers
- sample values

### 2. Normalize
Standardize where appropriate:
- whitespace
- state names
- constituency names
- MP names
- amount fields
- dates

Keep original values when useful.

### 3. Entity matching
Prefer:
1. Work ID / Unique Work Number
2. exact official identifier
3. normalized composite key
4. fuzzy matching only when justified

For fuzzy matching store:
- match method
- match confidence

Do not automatically merge low-confidence matches.

### 4. Master dataset
Only include facts supported by actual source data.

Possible fields:
- `work_id`
- `mp_name`
- `state`
- `constituency`
- `house`
- `work_category`
- `work_name`
- `work_description`
- `recommended_amount`
- `recommendation_date`
- `completion_date`
- `expenditure_amount`
- `expenditure_date`
- `implementing_agency`
- `vendor`
- `payment_status`
- `allocated_amount`
- `source_files`
- `match_confidence`

Only create fields that actually exist or can be safely derived.

### 5. Missing data
Use NULL/empty when unavailable. Never infer unsupported values.

### 6. Reproducibility
The master dataset must be generated by scripts, not manual copy/paste.
