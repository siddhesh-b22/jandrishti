⚖️ 2. Statutory Authority Hierarchy & Separation of Powers
Strict compliance with MoSPI operational guidelines across Indian public finance tiers.
RANK 1 MINISTRY_ADMIN Central MoSPI
National supervisory power. Can view all Indian states, configure system parameters, freeze suspicious dockets, and handle parliamentary questions.
Jurisdiction: Pan-India (National)
Workspaces: /workspaces/ministry
RANK 2 STATE_NODAL_AUTHORITY State Planning Dept
Reviews technical approvals from district collectors, manages state allocation quotas, grants statutory financial sanctions, or rejects non-compliant works.
Jurisdiction: Designated State (user.state)
Workspaces: /workspaces/state
RANK 3 DISTRICT_AUTHORITY District Collector / DM
Performs techno-economic scrutiny on MP recommendations, assigns implementing agencies/contractors, records field milestones, and uploads geo-tagged photos.
Jurisdiction: Designated District (user.district)
Workspaces: /workspaces/district
RANK 4 MEMBER OF PARLIAMENT Lok Sabha / Rajya Sabha
Drafts and submits constituency work recommendations within their annual entitlement (₹5 Crore). Tracks sanction velocity and project completion milestones.
Jurisdiction: MP Seat (user.mp_id)
Workspaces: /workspaces/mp
RANK 5 STATUTORY AUDITOR CAG / Forensic Auditor
Independent forensic oversight. Inspects statistical anomalies, cartel formation, and Benford flags. Creates formal audit cases and flags evidence.
Jurisdiction: National Independent Oversight
Workspaces: /workspaces/auditor
RANK 6 CITIZEN General Public
Open civic transparency. Can search any MP's performance, inspect local village works on interactive maps, and file ground discrepancy feedback.
Jurisdiction: Read-Only Public Corpus
Workspaces: /workspaces/citizen
🔒 Statutory Financial Immutability Rule (ABAC Enforcement) Fields such as sanctioned_amount, expenditure_amount, work_id, and internal_transaction_id strictly reject generic HTTP PUT/PATCH requests. Financial mutations can only occur via reconciled Treasury Voucher ledger operations with dual-signoff.
🔄 3. Statutory Recommendation Lifecycle State Machine
Guaranteed forward-only transitions defined in backend/workflow.py.
STEP 01
DRAFT
Auth: Member of Parliament
MP fills title, sector, estimated cost, location, and justification. Remains editable.
STEP 02
SUBMITTED
Auth: Member of Parliament
Proposal locked from further MP modification and dispatched to District Collector.
STEP 03
DISTRICT_REVIEW
Auth: District Authority
Collector performs technical feasibility, estimates validation, and site suitability check.
STEP 04
STATE_REVIEW
Auth: State Nodal Authority
State planning department reviews district approval against state budget quotas.
STEP 05
SANCTIONED
Auth: State Nodal Authority
Official administrative and financial sanction order released; fund commitment booked.
STEP 06
IN_PROGRESS
Auth: District Authority
Tender awarded; contractor deployed on ground; physical execution milestones tracked.
STEP 07
COMPLETED
Auth: District Authority
100% physical milestone reached; final expenditure voucher generated.
STEP 08
VERIFIED
Auth: District / State / Ministry
Geo-tagged photographic evidence validated. Asset registered on national public ledger.
↩️ Return for Correction & Rejection Paths If a proposal contains cost defects, the District Authority transitions it to RETURNED_FOR_CORRECTION, re-opening MP edit access. If a proposal falls under the MoSPI Prohibited Works List, it transitions to REJECTED (Terminal State).
🧠 4. Pre-Disbursement Forensic Audit Intelligence
Real-time statistical anomaly screening across 6 autonomous detection engines.
Forensic Engine Algorithmic Principle Default Weight Threshold Trigger
1. Semantic Duplication Levenshtein distance and Jaccard similarity across project titles, sectors, and GPS locations to flag duplicate work funding. 0.35 (35%) Similarity index > 0.85
2. Vendor Cartelization Herfindahl-Hirschman Index (HHI) calculating vendor revenue concentration and repeat contract capture in a single constituency. 0.25 (25%) HHI score > 2,500 (Monopolistic)
3. Benford's Law Analysis Chi-square and log-frequency goodness-of-fit test on the leading digits of disbursement voucher amounts. 0.20 (20%) p-value < 0.05 deviation
4. Expenditure Velocity Z-score standard deviation anomaly detector flagging uncharacteristic "March-rush" spending bursts before fiscal close. 0.20 (20%) Z-score > 3.0 standard dev
5. Predictive Delay Model Random Forest regression estimating expected completion timelines based on historical district performance. Auxiliary Signal Predicted delay > 180 days
⚡ 5. Step-by-Step Code Execution Trace (Front-to-Back)
How a user request executes across all system layers.
1

User Interaction in Frontend UI

An MP completes proposal details in frontend/src/pages/workspaces/MpWorkspace.tsx and clicks "Submit Recommendation".

2

HTTP Request Dispatch with JWT

frontend/src/api/client.ts attaches the stored session JWT to POST /api/v1/recommendations/submit.

3

Authentication & Statutory Identity Resolution

FastAPI invokes backend/auth.py::verify_bearer_token(), unpacking the token into an AuthenticatedUser object with role, state, and mp_id.

4

ABAC & Jurisdiction Boundary Interception

backend/rbac_abac.py::check_permission() verifies role privileges, checks field immutability, and ensures the MP only acts within their constituency boundary.

5

Workflow State Machine Transition Check

backend/workflow.py::validate_workflow_transition() verifies the current status is DRAFT and target is SUBMITTED, authorized only for ROLE_MP.

6

Database Mutation & Dual Engine Failover

backend/gov_service.py executes the SQL UPDATE via backend/db_engine.py, targeting Supabase PostgreSQL with transparent SQLite fallback.

7

Cryptographic Chained Audit Logging

backend/audit_logger.py::record_audit_log() appends a tamper-proof audit record containing timestamp, user_id, action, client IP, and state transition.

8

Response Serialization & UI Cache Invalidation

FastAPI serializes the updated record via Pydantic v2 schemas; the React client invalidates its cache and renders a success notification.

🔧 7. How to Customize & Extend Later
Quick guide for extending the platform with new roles or workflow rules.
1. Adding a New Role

1. Define constant in backend/rbac_abac.py.
2. Assign rank in ROLE_HIERARCHY_RANK.
3. Define action sets in ROLE_PERMISSIONS.
4. Add UI page in frontend/src/pages/workspaces/.

2. Modifying Workflow Rules

1. Edit RECOMMENDATION_TRANSITIONS in backend/workflow.py.
2. Map authorized roles in TRANSITION_AUTHORITY.
3. Add new status badge colors in frontend/src/utils/formatters.ts.

3. Tweaking Anomaly Weights

1. Adjust DEFAULT_WEIGHTS in backend/risk_engine.py.
2. Or use live REST API: PUT /api/v1/risk-weights to update weights dynamically without redeploying.
